# 一、前言
机台作为电玩场所核心的吸客与创收载体，其库存管理直接关系到场所日常运营效率、客户消费体验及整体盈利水平。当前电玩行业机台品类繁杂、更新迭代速度快，涵盖彩票、礼品、模拟体验等多种类型，对库存统筹、流转管控及数据追溯提出了极高要求，传统粗放式管理模式已难以适配行业发展节奏，易引发绑定混乱、数据异常、库存积压或短缺等问题。为规范机台库存全流程操作，明确各环节核心职责与操作标准，破解实操中的常见痛点，为一线运营及管理人员提供清晰可依的行动指南，同时优化库存管理体系、降低运营成本，特制定本指南。本指南适用于电玩场所机台库存相关的创建、配置、绑定、数据统计等全场景实操工作，旨在保障各环节衔接顺畅、数据精准可追溯。

# 二、机台库存使用整体流程
机台库存使用需遵循“基础配置→关联绑定→数据统计”的核心逻辑，形成完整操作闭环，各环节不可逆且环环相扣，必须严格按顺序执行，防止因步骤错乱导致后续数据异常。

## 2.1 整体流程框架
创建仓库→创建项目→创建机台→机台与仓库/对应商品（彩票/礼品）绑定→报表统计与数据应用

## 2.2 各环节实操说明
### 2.2.1 创建仓库
仓库是机台库存流转与存储统筹的核心载体，主要用于归集彩票、礼品等各类关联商品，实现商品收发存全流程管控。操作时需准确录入仓库名称、所属区域、负责人等关键信息，其中必填项严禁遗漏，避免对后续绑定环节造成阻碍，同时明确仓库管理范围。创建完成后，需逐一核对仓库信息准确性，确保无名称重复、区域错配等问题。

###### 案例①：门店进来是所有礼品和彩票都放到主仓库情况下
此情况则不需要额外建立其他仓库，直接使用系统默认建立的主仓库即可。后续所有采购的彩票和礼品都直接入库到此仓库即可。后续给机台加库存也是从主仓库调拨过去

###### 案例②：门店需要区分礼品仓库、彩票仓库和其他零售仓库情况。
此情况需要在系统中新增多个【普通仓库】，并且按照功能命名为礼品仓库、彩票仓库等。

新建仓库路径：后台→仓库→仓库设置→新增

### 2.2.2 创建项目（如果已经安装卡头，则这步已经在安装卡头时完成了）
项目模块用于对机台进行分类管理，可有效区分不同类型、不同区域或不同运营场景的机台，为后续机台归类统计及多维度数据分析提供支撑。操作时需填写项目编号、项目名称、项目类型（如彩票机项目、礼品机项目）、所属区域等信息，其中项目类型需与后续关联的机台类型精准对应，杜绝分类混乱。创建完成后，需及时对项目进行归档整理，方便后续机台关联时快速检索调用。

**此步骤核心目的**：在系统上建立对应的机台类型，用于后续新增游乐项目使用。

设置路径：后台→终端→项目分类→新增

### 2.2.3 创建机台（如果已经安装卡头，则这步已经在安装卡头时完成了）
机台是库存关联的核心主体，需依托已创建的项目完成配置，明确设备属性与运营定位。操作时需准确录入机台编号、机台名称、对应关联项目、摆放位置、设备型号等关键信息，确保机台信息唯一可识别且与实际设备完全一致。创建完成后，需重点校验机台与项目的关联准确性，确认无错绑、漏绑情况，为后续与仓库/商品的绑定环节筑牢基础。

**此步骤核心目的**：在系统上建立对应的游乐项目，用于统计各个机台的库存使用

设置路径：后台→终端→游乐项目→新增

### 2.2.3 创建机台仓库
机台仓库是整个机台库存管理的核心，需要新增机台仓库后才能实现库存管理，只有新增明细的仓库才能精细化管理好好管理号门店实际库存。该环节只需要一次性新增即可，但是对后续影响非常大，需要梳理清楚后再建立好对应仓库。

**此步骤核心目的**：在系统上建立对应游乐项目的仓库，用于每个仓库都能精细化管理。

###### 案例①：（简化版）门店只想知道所有的库存，不需要精细到所有机台都独立仓库情况下
优势：库存管理流程简单，适用用娃娃机场景，回收后直接又回到机台仓，减少库存管理步骤

缺点：只能掌握整体门店的库存，无法精细到每个机台的库存，也无法快速知道哪个机台库存少了。

此方案则需要提前设置好一个共用机台仓库，并同步后将各个P位的机台仓库重新选择为同一个仓库。

###### 案例②：（精细版）门店需要知道每个机台里面的库存数量，并精确管理对应的库存
优势：库存管理极其精细，有助于数据统计。

缺点：库存管理步骤相对较多。

此方案则直接同步机台库存即可，不需要额外修改库存。

设置路径：后台→机台库存管理→同步彩票机仓库/同步礼品机仓库/同步蓝票机仓库

### 2.2.4 机台与仓库/商品绑定
作为衔接机台与库存的关键环节，需根据机台类型差异化执行绑定操作，规避因操作统一导致的绑定错误，进而保障数据统计的精准性，该环节实操频次高、易出问题，需重点把控细节。

1. 彩票/蓝票类机台：绑定核心是实现彩票机与对应仓库的同步关联，操作时需在机台配置页面选中已创建的目标仓库，完成绑定后确保出票数据可实时同步至仓库库存统计系统。若发现绑定错误，需先解除原有绑定关系、清除数据残留，再按流程重新绑定，禁止直接修改关联信息，避免遗留数据隐患。
2. 礼品类机台：绑定核心是关联具体礼品商品，操作时需在机台配置页面选定对应礼品品类及具体商品，同步关联所属仓库，确保礼品的消耗、补给数据与机台运营数据实时联动。绑定前需确认礼品商品已完成库存系统录入，且仓库归属与礼品存储需求一致。

### 2.2.5 报表统计与数据应用
报表统计与数据应用是机台库存管理的收尾环节，也是价值输出环节。报表体系作为核心数据载体，可直观呈现机台经营状况、库存流转动态及核心指标表现，为运营决策提供可靠支撑。需基于已完成绑定的机台及库存数据，生成多维度报表，明确各报表的查询口径与适用场景，有效解决报表维度混淆、查询效率低下的问题，实现数据驱动运营。

![](https://cdn.nlark.com/yuque/0/2026/png/1584417/1776138007563-b55fa002-9436-42dc-97ba-8c8e7cb3f17b.png)

# 三、核心报表体系及解读
  
为便于不同岗位人员快速获取所需数据，机台库存相关报表按功能划分为经营数据报表、流转记录报表、核心指标报表三类，每类报表均明确统计维度、数据来源及应用场景，兼顾实用性与便捷性。

##   
3.1 经营数据报表
  
该报表核心统计机台营收、消费等经营数据，同步关联库存消耗情况，统计维度可按机台、会员、日期（日/周/月）、项目等灵活拆分。核心指标涵盖入币价值、消费数量、营收金额、库存消耗金额等，可用于分析单台机台盈利能力、不同项目经营差异，为机台摆放调整、运营策略优化提供数据依据。查询时需精准选择统计口径，避免跨维度数据混淆导致决策偏差。

##   
3.2 流转记录报表
  
此类报表分为出票记录报表、礼品流转记录报表两类，核心作用是追溯库存消耗与补给轨迹，实现库存变动全流程可查。其中，出票记录报表统计各机台出票数量、出票时间、对应会员（如有）等信息，同步关联仓库彩票库存变化；礼品流转记录报表统计礼品消耗数量、补给数量、消耗时间、对应机台等信息，确保每一笔库存变动都可精准追溯。若报表显示“暂无数据”，需优先排查机台与仓库/商品的绑定关系是否正常、数据同步是否及时，再检查设备网络连接状态及数据上传情况，必要时可重启设备或联系技术人员排查。

![](https://cdn.nlark.com/yuque/0/2026/png/1584417/1776138027761-6a77ca64-f8b9-46e8-9f09-9155c6776927.png)

## 3.3 核心指标报表
  
该类报表重点统计返奖概率相关数据，包括彩票返奖概率报表、礼品返奖概率报表，核心用于优化机台运营参数与库存配置。彩票返奖概率报表按机台统计出票返奖比例，为工作人员调整机台出票参数提供依据，实现营收与客户体验的平衡；礼品返奖概率报表统计各礼品机的礼品中奖比例，指导礼品采购与更换工作，避免因返奖率过高或过低影响客户留存及场所盈利。

# 四、常见问题及注意事项
##   
4.1 实操场景常见问题及排查方法


1. 绑定错误问题：若出现机台与仓库/商品绑定错误，需先解除原有绑定关系、清除关联数据残留，再按标准流程重新绑定，禁止直接修改关联信息；绑定前需仔细核对机台类型与仓库/商品类型的匹配性，杜绝彩票机绑定礼品仓库、礼品机绑定彩票仓库的情况。
2. 数据异常问题：当报表无数据或数据失真时，优先从三方面排查：一是确认机台、项目、仓库的创建顺序是否合规（需严格遵循“仓库-项目-机台”顺序，不可逆）；二是核查绑定关系是否正常，有无未绑定或绑定错误情况；三是检查设备网络连接是否稳定、数据是否同步上传，可通过重启设备排查基础故障，疑难问题及时联系技术人员处理。
3. 分类混乱问题：若因项目、机台分类混乱导致统计效率低下，需重新梳理分类标准，对已创建的项目、机台进行归档调整并补充分类标签，后续新增项目、机台时严格按统一标准录入，从源头规避分类混乱问题。



##   
4.2 通用注意事项




4. 信息录入规范：仓库、项目、机台的编号需保证唯一性，名称需简洁明了、精准标识，避免重复或模糊表述；类型、区域等关键字段严禁遗漏，确保信息可快速检索、核对，为后续操作奠定基础。
5. 操作流程不可逆：需严格遵循“创建仓库-创建项目-创建机台-绑定-报表”的既定流程，若跳过某一步骤或颠倒顺序，将导致后续操作无法正常开展，届时需删除已创建信息重新操作，大幅增加工作成本。
6. 数据定期核对：每日运营结束后，需同步核对机台运营数据与库存流转数据，确保两者一致；每周开展一次全面排查，及时发现并解决潜在数据异常问题，避免问题积累影响后续运营决策的科学性。
